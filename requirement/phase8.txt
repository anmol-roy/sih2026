# PHASE 8 — Multilingual Layer + Bhashini

Now we cover another **explicit requirement** without overbuilding it.

> **Goal:** The same grounded IP answer should work in multiple Indian languages while **preserving citations, legal terms, section numbers, and confidence**.

For your SIH prototype, don't translate the entire corpus. Build a **query → retrieval → answer → translation** pipeline.

---

# 1. What Phase 8 should achieve

Example:

```text
User asks in Hindi
        ↓

        ↓
Hindi → English
        ↓
Existing IP-SAKTI pipeline
        ↓
English grounded answer
        ↓
English → Hindi
        ↓
Hindi answer
        ↓
Same citations
```

For prototype, support:

```text
English
Hindi
Kannada
```

You can add more later.

# 2. Important architecture decision

**Do NOT translate your entire PDF corpus.**

Keep:

```text
Original authoritative documents
            ↓
        English corpus
```

Then:

```text
User language
      ↓
Translate query
      ↓
English retrieval
      ↓
English evidence
      ↓
Generate grounded answer
      ↓
Translate answer
```

This avoids:

```text
❌ storing 10 copies of every document
❌ translation inconsistencies
❌ huge vector database
❌ losing legal terminology
```

# 4. Create language schema

Create:

```text
src/
└── multilingual/
    └── schemas.py
```

```python
from enum import Enum
from pydantic import BaseModel


class Language(str, Enum):

    ENGLISH = "en"
    HINDI = "hi"
    KANNADA = "kn"


class LanguageResult(BaseModel):

    language: Language

    confidence: float
```

---

# 5. Detect language

Create:

```text
src/multilingual/detector.py
```

For the prototype, use a lightweight language detector.

```python
from langdetect import detect

from schemas import Language


LANGUAGE_MAP = {
    "en": Language.ENGLISH,
    "hi": Language.HINDI,
    "kn": Language.KANNADA,
}


def detect_language(text: str):

    detected = detect(text)

    return LANGUAGE_MAP.get(
        detected,
        Language.ENGLISH
    )
```

Add:

```text
langdetect
```

to `requirements.txt`.

---

# 6. Don't blindly trust language detection

Short queries can be difficult:

```text
"Patent kya hai?"
```

A language detector may struggle.

So keep:

```json
{
    "language": "hi"
}
```

as an optional API parameter.

User-selected language should override automatic detection.

# 8. Translation layer

Create:

```text
src/
└── multilingual/
    └── translator.py
```

For development, you can initially use your existing LLM.

```python
from langchain_groq import ChatGroq


llm = ChatGroq(
    model="llama-3.3-70b-versatile",
    temperature=0
)


def translate_to_english(text: str, language: str):

    if language == "en":
        return text

    prompt = f"""
Translate the following intellectual-property query
into English.

Preserve:

- Legal terminology
- Section numbers
- Act names
- Patent terminology
- Trademark terminology
- Scientific names
- Ingredient names

Do not add information.

Language:
{language}

Text:
{text}
"""

    response = llm.invoke(prompt)

    return response.content
```

# 9. Why translation must happen BEFORE retrieval

Suppose the user asks:

> क्या धारा 3(p) पारंपरिक ज्ञान से संबंधित है?

You want:

```text
Hindi
 ↓
"Is Section 3(p) related to traditional knowledge?"
 ↓
Retriever
 ↓
Patents Act
Section 3(p)
```

Not:

```text
Hindi
 ↓
Embedding
 ↓
Random Hindi/English chunks
```

Your authoritative corpus remains centralized.

# 10. Preserve legal identifiers

This is critical.

Your translation system must **never translate**:

```text

TRIPS
IPC

```

For example:

❌ Bad:

```text

```

Better:

```text
Section 3(p)
```

You can explain it in Hindi afterward.

# 12. Translate only the answer

Now:

```text
English Answer
      ↓

```

But keep citations as structured data.

Don't send:

```text

```

Instead:

```json

            "page": 8

```

Translate only:

```text
answer
```

Then attach:

```text

```

again.

# 13. Create answer schema

```text
src/multilingual/schemas.py
```

```python
from typing import List
from pydantic import BaseModel


class Citation(BaseModel):

    document: str

    section: str | None = None

    page: int | None = None

    source: str


class GroundedAnswer(BaseModel):

    answer: str

    citations: List[Citation]

    confidence: float
```

Now translation cannot accidentally destroy your citations.

# 14. Translate the answer

```python
def translate_answer(
    answer: str,
    target_language: str
):

    if target_language == "en":
        return answer

    prompt = f"""
Translate this intellectual-property information
into {target_language}.

Rules:

1. Preserve legal meaning.
2. Do not change Section numbers.
3. Do not change Rule numbers.
4. Do not translate official Act names unless
   an explanatory translation is useful.
5. Preserve scientific names.
6. Do not add legal conclusions.
7. Do not remove uncertainty.
8. Do not add information.

Text:

{answer}
"""

    response = llm.invoke(prompt)

    return response.content
```

---

# 15. Preserve confidence

Suppose English pipeline returns:

```json
{
    "confidence": 0.82
}
```

Hindi output must still be:

```json
{
    "confidence": 0.82
}
```

Translation should **never recalculate confidence**.

Same for:

```text
citations
sources
jurisdiction
IP type
human escalation
```

# 17. Bhashini integration

Once the basic multilingual pipeline works, add Bhashini as the **Indian-language infrastructure layer** rather than making your entire application dependent on it from day one.

Architecture:

```text
User
 ↓
Language Detection
 ↓
┌─────────────────────────┐
│ Language Service        │
│                         │
│ Bhashini / fallback LLM │
└─────────────────────────┘
 ↓
English normalized query
 ↓
IP-SAKTI
 ↓
Grounded answer
 ↓
Bhashini / fallback
 ↓
User language
```

For your prototype, the important thing is to demonstrate the **integration point**, not build an enormous language infrastructure system.

# 18. Add a translation provider abstraction

Don't hard-code Bhashini everywhere.

Create:

```text
src/
└── multilingual/
    ├── translator.py
    ├── bhashini.py
    └── provider.py
```

```python
class TranslationProvider:

    def translate_to_english(
        self,
        text: str,
        language: str
    ):
        raise NotImplementedError

    def translate_from_english(
        self,
        text: str,
        language: str
    ):
        raise NotImplementedError
```

Then:

```text
TranslationProvider
        │
        ├── BhashiniProvider
        │
        └── LLMTranslationProvider
```

This gives you a fallback if the external service is unavailable.

# 20. Multilingual guardrails

You must preserve the same guardrails after translation.

English:

> "This information is not legal advice."

Hindi:

> "यह जानकारी कानूनी सलाह नहीं है।"

Kannada:

> "ಈ ಮಾಹಿತಿಯು ಕಾನೂನು ಸಲಹೆಯಲ್ಲ."

The translated version must not weaken or remove the disclaimer.

# 23. Measure three things

Don't only check whether the translation "sounds good."

Measure:

### Retrieval consistency

```text
English → Section 3(p)
Hindi → Section 3(p)
Kannada → Section 3(p)
```

### Citation consistency

All languages should cite the **same source**.

### Meaning consistency

The answer should not change legal meaning.

Your evaluation table:

```text
| Question | EN | HI | KN |
|----------|----|----|----|
| Retrieval | ✓ | ✓ | ✓ |
| Citation | ✓ | ✓ | ✓ |
| Meaning | ✓ | ✓ | ✓ |
```
